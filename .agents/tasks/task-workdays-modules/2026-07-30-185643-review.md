# HR modules: Employee Edit, Absences, Remuneration, Dynamic Dashboard (v2)

This second pass reviews the same branch after fixes from commit `025a866` addressed seven of eight issues raised in v1. The compensating delete on partial failure, seniority double-count fix, timezone-safe local date formatting, dynamic year dropdowns, mocked-events badge, unused import removal, and standardized Supabase client instantiation are all confirmed resolved. RLS/auth enforcement was intentionally deferred (roadmap priority #5) and is not re-flagged here.

Watch for: A residual `toISOString()` call in the calendar page's "today" highlight can still misidentify the current day for Belgian users (confirmed, low severity — visual-only).

**Verdict**: APPROVED

## High-level view

The absence booking wizard now performs a compensating delete of the `holiday_selections` row when the `year_calendar` insert fails. The compensating delete is fire-and-forget — if it also fails, the orphan persists silently — but the user receives the original error and can retry, making this acceptable for the current scale.

The salary simulator's seniority logic was refactored so `granted_seniority_date` is treated as the already-adjusted anchor without stacking `granted_seniority` on top.

The dashboard and booking wizard switched to manual `YYYY-MM-DD` construction using local date getters. One instance in the calendar view's "isToday" comparison was missed — it still uses the unsafe `toISOString()` pattern. The impact is cosmetic (wrong day highlighted between midnight and 02:00 CEST, no data corruption).

Year dropdowns now derive dynamically from `new Date().getFullYear()`.

## Residual timezone pattern in the calendar view

The calendar page constructs `dateStr` correctly using local components:

```typescript
const dateStr = `${year}-${String(month + 1).padStart(2, "0")}-${String(day).padStart(2, "0")}`;
```

But the "isToday" comparison still uses the UTC-based pattern:

```typescript
const isToday = new Date().toISOString().split("T")[0] === dateStr;
```

Between midnight and 01:00 CET (or 02:00 CEST), `toISOString()` returns the previous UTC day while `dateStr` reflects the correct local day. The inconsistency is with the local-date pattern used in the same file's `startOfMonth`/`endOfMonth` construction and in the dashboard and booking wizard after the v1 fixes.

Fix:

```typescript
const now = new Date();
const todayStr = `${now.getFullYear()}-${String(now.getMonth() + 1).padStart(2, "0")}-${String(now.getDate()).padStart(2, "0")}`;
const isToday = todayStr === dateStr;
```

## Compensating delete caveat

The compensating delete after a failed `year_calendar` insert is fire-and-forget:

```typescript
if (calError) {
  await supabase
    .from("holiday_selections")
    .delete()
    .eq("id", selectionData.id);
  setError(calError.message);
  ...
}
```

If the delete itself fails (network blip, RLS denial), the orphaned `holiday_selections` row persists without the user knowing. At the current scale this is unlikely to matter, but a production hardening pass should log or surface that secondary failure.
